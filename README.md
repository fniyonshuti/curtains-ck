# React + Vite

## Supabase setup

The admin product form uploads images to Supabase Storage and saves product
data in Supabase Database.

1. Create a Supabase project at [supabase.com](https://supabase.com).
2. In **SQL Editor**, run:

```sql
create table public.products (
	id bigint generated by default as identity primary key,
	name text not null,
	category text not null,
	price numeric(10, 2) not null,
	rating numeric(2, 1) not null default 5.0,
	image_url text not null,
	description text not null,
	created_at timestamptz not null default now()
);

alter table public.products enable row level security;

create policy "Anyone can view products"
on public.products for select
to anon, authenticated
using (true);

create policy "Demo admin can add products"
on public.products for insert
to anon, authenticated
with check (true);
```

To enable real customer ratings, also run:

You can paste the SQL below into Supabase SQL Editor, or run the complete
rerunnable script in [supabase/product-ratings.sql](supabase/product-ratings.sql).

```sql
create table public.product_ratings (
	id bigint generated by default as identity primary key,
	product_id bigint not null references public.products(id) on delete cascade,
	reviewer_id text not null,
	reviewer_name text,
	rating integer not null check (rating between 1 and 5),
	feedback text,
	created_at timestamptz not null default now(),
	unique (product_id, reviewer_id)
);

alter table public.product_ratings enable row level security;

create policy "Anyone can view product ratings"
on public.product_ratings for select
to anon, authenticated
using (true);

create policy "Anyone can submit product ratings"
on public.product_ratings for insert
to anon, authenticated
with check (true);

create policy "Anyone can update their product ratings"
on public.product_ratings for update
to anon, authenticated
using (true)
with check (true);
```

The website stores a browser-specific reviewer ID and allows that browser to
submit or update one rating per product. For stronger identity verification in
production, replace this with Supabase Auth user IDs.

3. In **Storage**, create a public bucket named `curtain-images`.
4. In **Storage > Policies**, add these policies:

```sql
create policy "Anyone can view curtain images"
on storage.objects for select
to anon, authenticated
using (bucket_id = 'curtain-images');

create policy "Demo admin can upload curtain images"
on storage.objects for insert
to anon, authenticated
with check (bucket_id = 'curtain-images');
```

5. Copy `.env.example` to `.env.local` and replace both placeholder values
   with the project URL and anon key from **Project Settings > API**.
6. Restart the Vite server with `npm run dev`.

The current login (`admin` / `admin123`) is only a demo login. Before deploying,
replace it with Supabase Auth and restrict the insert policies to authenticated
admin users.

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the Oxlint configuration

If you are developing a production application, we recommend using TypeScript with type-aware lint rules enabled. Check out the [TS template](https://github.com/vitejs/vite/tree/main/packages/create-vite/template-react-ts) for information on how to integrate TypeScript and Oxlint's TypeScript related rules in your project.
